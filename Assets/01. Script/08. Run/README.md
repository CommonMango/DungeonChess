# RunState와 의지

RunState는 씬 오브젝트를 참조하지 않는 런 데이터입니다. RunManager가 현재 RunState를 메모리에 보유합니다.
용병단·증강·진행 정보는 이후 RunState에 추가할 대상이며 이번에는 해당 저장 구조나 기존 매니저를 이관하지 않았습니다.

## API

```csharp
RunState run = RunManager.EnsureRun(); // 없을 때만 생성, 씬 재진입으로 초기화하지 않음
run.ReduceWill(20);                   // 실제 감소량 반환
run.RecoverWill(10);                  // 실제 회복량 반환
int will = run.CurrentWill;
bool failed = run.IsWillDepleted;
RunManager.StartNewRun(100, 100);      // 초기 의지, 최대 의지. 새로운 RunId와 상태 생성
```

- 기본 100/100은 사용자 승인된 테스트 수치이며 최종 기획 확정이 아닙니다.
- 초기 의지는 1 이상, 최대 의지 이하이며 최대 의지는 1 이상이어야 합니다.
- 감소는 0, 회복은 최대 의지에서 제한합니다. 음수 입력은 예외로 거부합니다.
- 의지 0은 실패 판정입니다. 회복으로 실패한 원정을 부활시키지 않으며 새 런으로 시작합니다.
- 새 런 생성 인자가 잘못되면 현재 런을 유지하고 예외를 반환합니다.
- NodeMap의 Start는 EnsureRun, 기존 새 도전은 StartNewRun을 호출합니다.
- 전투 시작 시 EnsureRun을 호출하므로 전투 씬 단독 실행에서도 런이 생성됩니다.
- 상태는 씬 전환 시 유지됩니다. 프로그램 종료, Play 재시작 및 스크립트 도메인 재로드 이후 이어하기를 위한 디스크 저장/불러오기는 이번 범위가 아닙니다.
- Domain Reload를 꺼도 Play 시작 시 이전 세션의 상태를 초기화합니다.

## 범위

의지 UI와 이벤트는 추가하지 않았습니다. 패배 피해와 노드 진행 연동은 아래 규칙을 사용합니다.
기존 AugmentManager와 노드 진행 상태의 저장 위치도 이번에는 변경하지 않았습니다.

## 검증

100→70 감소, 회복, 과도한 감소/회복 제한, 음수 거부, 0 이후 회복 차단, 런 객체 유지, 새 런 교체를 확인했습니다.
NodeMap의 새 도전과 씬 재로드 후 의지 유지도 확인했습니다.

## 전투 패배 피해

UnitData의 `willDamage`에 해당 적이 살아남았을 때의 의지 피해를 지정합니다.

| 적 분류 | willDamage |
| --- | ---: |
| 일반 잡몹 | 5 |
| 원거리 / 마법사 | 7 |
| 강한 전열 | 8 |
| 엘리트 | 15 |

- 새 SO의 기본값은 5입니다. 원거리/마법사·전열·엘리트는 SO에서 각각 7·8·15로 지정합니다. 이름이나 능력치로 자동 분류하지 않습니다.
- 기존 eyeMonster SO는 일반 적으로 5를 적용했습니다.
- 보스는 `isBoss`를 켭니다. 일반 합산에서 제외하며, 보스 별도 피해 공식은 아직 미구현입니다. 따라서 현재 보스 자체로 인한 의지 차감은 없습니다.
- UnitManager에 등록된 활성 상태이며 HP가 0보다 큰 적의 값만 합산합니다. 아군·사망·비활성 유닛은 제외합니다.
- PhaseManager에서 Battle → Lose 전환 시 구독자 호출 전에 한 번 적용합니다. 승리나 씬 정리에서는 차감하지 않습니다.
- 음수 피해는 0으로 취급하며 합계는 int 최댓값, 실제 의지는 0에서 제한합니다.
- 패배 후 의지가 남으면 해당 노드를 완료하고 다음 경로로 진행합니다. 의지가 0이면 원정 실패이며 새 도전으로 초기화합니다.
- 테스트: 5+7+8+15=35, 보스/사망 제외, 음수/오버플로 방어, 승리 무차감, 중복 차감 방지, 65 의지로 맵 복귀 및 다음 전투, 의지 0 실패 및 새 런 100 초기화 통과.
